# Bluetooth-протокол тега (прошивка v19)

Для тех, кто пишет свой клиент (приложение, скрипт, Home Assistant). Всё прочитано из исходников прошивки
(`firmware/ble_badge.c`, `cmd_set.c`, `slot.c`, `ota.c`, `nfc.c`, `od.c`); эталонный клиент — страница `web/index.html`.
Пометки: **[OK]** проверено на реальном теге, **[code]** прочитано из кода и покрыто тестами на хосте, на теге со сторонним клиентом не проверялось,
**[?]** не проверено.

## 1. Транспорт

| Что | Значение |
|---|---|
| Свой сервис | `b9220000-5c1e-4f6a-9d3b-0a7c6e1f2d40` |
| `rx` (клиент → тег) | `b9220001-…` запись и запись без ответа, до 244 байт |
| `tx` (тег → клиент) | `b9220002-…` уведомления (и чтение), до 244 байт |
| Сервис OpenDisplay | `0x2446`, одна характеристика `0x2446` (чтение, запись, запись без ответа, уведомления), см. раздел 9 |
| Уведомления | клиент сначала включает их на `tx`; одно уведомление несёт не больше MTU − 3 байт |
| MTU | 23, пока стек клиента не договорится о большем (тег принимает то, что дали). Размеры блоков ниже зависят от MTU |

К тегу можно подключиться только в **окне**: после включения питания, после касания NFC или нажатия кнопки (`wt` секунд, по умолчанию 60) и после
окончания соединения. Окно показывает синяя вспышка каждые 5 с; когда оно закончилось, тег дважды мигает синим. В режиме OpenDisplay (настройка
`mode` = 1) тег доступен всё время. Соединение, в котором ничего не происходит, тег закрывает.

От тега к клиенту идут сообщения двух видов, различаются по первому байту:

* **текстовая строка**: первый байт — печатный ASCII (0x20..0x7E), текст UTF-8 без конца строки, не больше 96 байт. Большинство ответов — текстовые строки.
* **двоичное**: первый байт ≥ 0x80 (ответы `cmd | 0x80`, раздел 3), `0xC0` — данные слота (раздел 4), `0x00` — ответы OpenDisplay (раздел 9).

Пока на соединении клиент OpenDisplay, текстовые строки не отправляются вообще.

**Защита касанием.** Команды, заменяющие прошивку (начало OTA), переписывающие NFC-чип, меняющие имя, режим или окна, принимаются только
в течение 60 с после того, как кто-то коснулся тега телефоном (поле NFC) или нажал кнопку. Иначе ответ:
`ERR tap: touch the tag with the phone, repeat` (OTA: `OTA FAIL tap: …`). Состояние показывает `4F 19`. Слайды, обычные настройки и чтение не защищены.

## 2. Панели и картинки

| Тег | Панель | Пикселей (x × строк) | Байт в кадре |
|---|---|---|---|
| Solum EL016F5W4C / F6W4A | EL016 | 200 × 200 | 10 000 |
| Solum EL022F5C4C | EL022 | 160 × 296 (развёртка) | 11 840 |

`4F 1A` отвечает `PANEL <имя> <w>x<h> mirror=<0|1> ctrl=<hex> tag=<hex>` (`PANEL ? 0x0 …` — неизвестная панель: тег работает по Bluetooth, но рисовать не может).

**Кадр**: 2 бита на пиксель, четыре пикселя в байте, **левый пиксель в двух старших битах**, строки сверху вниз, без выравнивания:
`0` чёрный, `1` белый, `2` жёлтый, `3` красный. Кадр — `w*h/4` байт. Так страница отправляет кадр и так прошивка его хранит; в порядок развёртки панели
прошивка переводит сама. У прошивки есть одно базовое преобразование на панель, чтобы кадр, нарисованный на странице прямо, был прямым и на теге;
настройка `ориентация` (`4D`) поворачивает картинку поверх него: бит 0 — отражение по вертикали, бит 1 — по горизонтали, для всех хранимых форматов.
Базовое преобразование v19 — **[?]**, пока кнопку «Тест ориентации» не увидели на обоих тегах.

## 3. Двоичные команды

Запрос: `cmd args…` одной записью. Ответ: `cmd|0x80, status, data…` (status `00` ок, `FE` неверная длина, `FF` неизвестная команда).

| Cmd | Что делает | Данные ответа |
|---|---|---|
| `01` | ping | `PONG` |
| `02` | информация | версия прошивки (u16 LE), батарея мВ (u16 LE), тип тега (u8), причина последнего закрытия (u16 LE) |
| `03 …` | эхо | те же байты |
| `04 b` | проверка светодиода, один байт с битами цвета | – |
| `10` | JEDEC-id внешней флеш | 3 байта (status 01 — флеш не отвечает) |
| `11 a2 a1 a0 n` | прочитать n ≤ 50 байт внешней флеш | n байт |
| `12` | самопроверка последнего сектора: стирание, запись, сверка | мс стирания, мс записи, индекс ошибки (по u16 LE) |

## 4. Слоты

32 слота (0..31) во внешней флеш, секторы по 4 КБ, область 0x3C000..0x7CFFF; слот — заголовок и поток. Форматы потока
(`fmt`): `0` сырой кадр, `1` поток блока LZ4 с кадром, `2` каждая строка XOR со строкой выше, затем LZ4 (смещения ≤ 2048). Все ответы — текстовые строки.

| Команда | Что делает | Ответы |
|---|---|---|
| `40` | список | по строке `slot N: fmt F, L bytes, S sectors, crc=XXXXXXXX` на занятый слот, затем `slots: U used, F of T sectors free, largest run R, max 32 slots` |
| `41 N` | стереть слот N (`41 FF` — все) | `ERASED slot N` / `ERASED all` / `ERR busy` |
| `42 N len32 crc32 win fmt` | начать загрузку в слот N: длина потока, CRC-32 (zlib) потока, блоков на подтверждение (1..32, по умолчанию 8), формат | `UP READY chunk=C win=W mtu=M rx=244 fmt=F sect=S` или `UP FAIL <причина>` (`short`, `slot`, `panel`, `fmt`, `len`, `flash`, `erase`) или `slot N: no room …` |
| `43 seq16 data…` | один блок (не больше C байт), `seq` с 0 | `UP ACK <байт всего>` после каждых `win` блоков и после последнего; `UP FAIL seq A expected B`, `UP FAIL <причина>` |
| `44` | конец загрузки | `UP OK slot N crc=XXXXXXXX` или `UP FAIL crc` |
| `49` | прервать загрузку | `UP ABORT` / `UP idle` |
| `45 N` | нарисовать слот N сейчас (около 25 с) | `DRAW slot N`, затем `DRAW done` / `DRAW fail` / `DRAW no slot` |
| `4C` | нарисовать следующий слайд | как `45` |
| `47 N` | проверить хранимый слот (CRC и разбор) | `VERIFY slot N ok crc=…` / `FAIL crc=…` / `FAIL decode` / `empty` |
| `48` | MTU | `MTU mtu=M rx=244` |

Длина сырой загрузки должна быть ровно равна кадру панели. Сжатые потоки проверяются при разборе (ровно столько строк, сколько нужно).
Страница шлёт `win` блоков и ждёт `UP ACK` перед следующей группой. Пока идёт рисование, тег на другие команды не отвечает (радио делится с драйвером панели);
дождитесь `DRAW done`.

`4F 13 N` читает слот N обратно (миниатюры): `DUMP N fmt F len L crc=…`, затем двоичные кадры `C0 N seq16 data…` (до 90 байт хранимого потока), затем `DUMP done N`.

## 5. Слайдшоу и настройки

Все ответы — текстовые строки; настройки сохраняются в теге (два сектора флеш, новая копия при каждом изменении).

| Команда | Что делает | Ответ |
|---|---|---|
| `4B` | прочитать слайдшоу | `SS en=E every=S mask=HEX poll=O clean=N/M cur=C next=X` |
| `4A en every_lo every_hi mask0 order [clean_n clean_mode [mask1 mask2 mask3]]` | слайдшоу: вкл/выкл, интервал в минутах (1..1080), маска слайдов (бит на слот, `mask0` — биты 0..7 …), порядок 0 по кругу / 1 по номеру, полная перерисовка каждые `clean_n` слайдов в режиме 0/1/2 | `SS …` |
| `4D mode slot [lut]` | ориентация 0..3 (раздел 2), слот для OpenDisplay (0..31), байт таблицы цветов (`E4` — без изменений) | `OD mode=M slot=S lut=XX` |
| `4E name…` | хвост имени, 1..5 печатных символов (пусто — по умолчанию) **(защита касанием)** | `NAME saved, reboot (4F A5) to use it` |

Подкоманды `4F <sub> …`:

| Sub | Что делает | Ответ |
|---|---|---|
| `01 n` | мощность передатчика 0..5 (−15 … +6 дБм) | `TX n` |
| `03` | состояние системы | `SYS tx= wd= led= v= mode= wt= wb= tap= sw= ct= tc=` |
| `04 n` | яркость светодиода 0..3 | `LED n` |
| `05 m` | режим 0 обычный, 1 OpenDisplay, перезапуск **(защита касанием)** | `MODE m, restarting` |
| `06 wt wb` | окна Bluetooth после касания / при включении, 10..250 с **(защита касанием)** | `WINDOWS tap= boot=` |
| `08 n` | 1: касание тега также рисует следующий слайд, 0: нет | `TAP next=n` |
| `09` | журнал событий | `EVENTS n`, затем строки `EV t name a b` |
| `0A [1]` | закрыть соединение (1: и окно) | – |
| `0B` | сохранённые настройки | `CFG or=<ориентация> od=<слот> lut=XX nm=<имя>` |
| `0C [en itv mask [win]]` | маячок BTHome, чтение или запись | `BT en= itv= mask= win=` |
| `0D` | id чипа, причина сброса, загрузчик, стек | `ID …`, `RST rc= fw=`, `BTL main= props= id=`, `STK free= of=` |
| `0E` | батарея | `BAT mv= min= ever= pct= low= draws=` |
| `10` | датчик температуры панели | `PT nC` / `PTEMP n/a` |
| `11 k` | картинка, сделанная прошивкой: 1 заставка, 2 полосы, 3 белая, 4 чёрная, 5 жёлтая, 6 красная, 7 шахматка, 8 рамка с F и UP; `20` — цикл очистки (2 мин) | `PIC k start` / `PIC k done` / `CLEAN …` |
| `12 [off]` | заставка при включении вкл/выкл | `SPLASH off=n` |
| `14 r g b [t]`, `15 …`, `16 …`, `17 …` | проверки светодиода, маячок-локатор, оттенок янтарного | `LEDT`, `LEDP`, `BEACON …`, `AMBER g=` |
| `18`, `1B`, `19` | NFC-чип, раздел 7 | |
| `1A` | панель | `PANEL …` (раздел 2) |
| `A5` | перезапуск | `REBOOT` |

Ошибки: `ERR short`, `ERR range`, `ERR busy`, `ERR tap: …`, `ERR cmd 4F xx` (неизвестная).

## 6. Обновление прошивки (OTA)

Новая прошивка — файл GBL (артефакт сборки `…ota.bin`) с отметкой продукта `BG22BADG`. Его записывают в слот загрузчика
(внешняя флеш 0..0x3B000), и после перезапуска его ставит загрузчик Gecko.

| Команда | Что делает | Ответ |
|---|---|---|
| `46 00` | состояние | `OTA st= got= len= btl= cap= room= fw= minmv=` |
| `46 01 len32 crc32 win` | начало (**защита касанием**; длина 64..0x3B000, CRC-32 всего файла, блоков на подтверждение); стирает старый образ | `OTA READY chunk=C win=W mtu=M` или `OTA FAIL <причина>` |
| `46 02 seq16 data…` | блок | `OTA ACK <байт>` за каждые `win` блоков; `OTA FAIL seq A expected B` |
| `46 03` | проверка: длина, CRC-32 по данным, прочитанным из флеш, заголовок GBL, CRC End-тега, отметка продукта | `OTA OK len= crc= gbl=1 product=1` или `OTA FAIL incomplete / crc / no end tag / not a gbl file / wrong product / readback / gbl crc` |
| `46 04 A5` | установка: перезапуск в загрузчик (нужны проверенный образ и батарея не ниже `minmv`) | `OTA INSTALL bootloader takes over, reconnect in about 40 s` |
| `46 05` | прервать | `OTA ABORT` |

После установки тег около 40 с не отвечает; новая `Info` показывает новую версию прошивки.

## 7. NFC-чип

Чип (TNB132M, NFC Forum Type 3 по I²C) хранит одну запись NDEF. Для любой записи нужна защита касанием; после записи чип читается обратно.
Пределы: ссылка до 120 байт печатного ASCII, текст до 120 байт корректного UTF-8, имя сети Wi-Fi до 32 байт, ключ до 63 байт; и не больше, чем вмещает чип (`cap` блоков по 16 байт).

| Команда | Что делает |
|---|---|
| `4F 18` | прочитать; `4F 18 url…` пишет ссылку (старая форма) |
| `4F 1B 00 url…` | записать ссылку (запись URI) |
| `4F 1B 01 text…` | записать текст (запись Text, язык `en`, UTF-8) |
| `4F 1B 02 auth ssid 00 key` | записать доступ к Wi-Fi (MIME `application/vnd.wfa.wsc`, TLV учётных данных); `auth` 0 открытая, 1 WPA2-personal, 2 WPA/WPA2-personal; открытая сеть: пустой ключ. **Ключ хранится в открытом виде, его прочтёт любой с телефоном.** |
| `4F 19` | состояние защиты: `TAP open=1 left=NNs` |

Ответы: `NFC written` или `NFC ERR n` (1 шина, 2 аргумент или слишком большой для чипа, 3 сверка, 4 занято), затем всегда
`NFC present=P r25=R len=L cap=C kind=K` (kind 0 пусто, 1 ссылка, 2 текст, 3 Wi-Fi, 4 другое), `NFC text=<что записано: ссылка, текст или имя сети, ключ никогда>` и,
если длиннее 80 байт (обрезка между двумя символами), `NFC text+=<остаток>`.

## 8. Диагностическая сборка

Сборка с `-DBG_DIAG` (собирается вместе с обычной, файлы `…_diag`) добавляет `4F 0F` («карточка железа»: выводы, ответы NFC, заводская страница данных, первые 128 байт таблицы
SFDP внешней флеш с её JEDEC-id, трасса шин панели и NFC). См. `docs/DIAG.ru.md`.

## 9. Совместимость с OpenDisplay

Тег понимает часть протокола OpenDisplay (opendisplay.org, эталонные клиенты `py-opendisplay`, интеграция Home Assistant `opendisplay`).
Использованные страницы спецификации: обзор протокола, протокол обмена (BLE flow), формат данных дисплея. Со сторонним клиентом на реальном теге пока не проверялось **[?]**.

Что делает тег:

* **GATT**: сервис `0x2446` с одной характеристикой `0x2446` (чтение, запись, запись без ответа, уведомления). Клиент включает уведомления и пишет
  сообщения `00 cmd …`; ответы приходят уведомлениями `00 cmd data` (успех) или `FF cmd` (ошибка) на той же характеристике. Те же сообщения работают и на своей паре `rx`/`tx`.
* **Реклама** (только в режиме OpenDisplay, `4F 05 01`): флаги, сервис `0x2446`, производитель-специфичные данные с company id `0x2446` и записью в 16 байт (ту же запись возвращает `00 44`);
  scan response: имя `OD` + три последних байта адреса в hex. Без режима OpenDisplay тег рекламирует собственное имя `pin16-…` в своих окнах.
* **Команды**: `00 40` чтение конфигурации (кадрирование: длина, версия 1, пакеты, CRC-16/CCITT-FALSE по всему, кроме CRC, байты длины считаются нулевыми;
  блоки `00 40 idx16 [total16] data`); отдаются пакеты: system (1), manufacturer (2), power (4), display (32: размер развёртки панели, цветовая схема 3 = BWRY, поворот 0,
  режим передачи только бит 3 = прямая запись, без сжатия); `00 43` версия прошивки (`major, minor, длина, текст, patch`: раскладка эталонной прошивки, patch = номер прошивки); `00 44` данные производителя (16 байт);
  `00 50` аутентификация (отвечает статусом `03`: шифрование не включено); `00 0F` перезапуск.
* **Прямая запись**: `00 70` (пустая нагрузка; нагрузка с размером означает сжатие, оно отклоняется ответом `FF 70`), `00 71 data…` (каждый блок подтверждается `00 71`), `00 72` конец (необязательные
  режим обновления и etag игнорируются). Кадр попадает в слот OpenDisplay (`4D`, по умолчанию 31) и рисуется; затем `00 73` (обновлено) или `00 74` (сбой или нет слота). Формат пикселей: схема 3 BWRY,
  2 бита, чёрный 0, белый 1, жёлтый 2, красный 3, левый пиксель в старших битах: как в разделе 2. Кадр — `w*h/4` байт.

Чего нет: частичное обновление (`00 76`), светодиод (`00 73` как команда, `00 75`), зуммер, сжатая прямая запись (zlib), шифрование AES-CCM (обмен ключом интеграции не предлагается),
`00 41/42` запись конфигурации, `00 45`, DFU `00 51`, NFC-точка OpenDisplay `00 83` (у тега свои команды NFC, раздел 7), Wi-Fi/LAN, несколько дисплеев.

Не проверено; проверить на реальном клиенте или по исходникам эталона (`Firmware-silabs-bg22`, `opendisplay_structs.h`), прежде чем на это полагаться:
(v20 следует раскладке эталона: запись = company id, 11 байт `FF`, температура `(T + 40) * 2`, батарея в единицах 10 мВ с 8-м битом в байте статуса, счётчик цикла в старшей тетраде; `00 43` = `major, minor, длина, текст, patch`.)
По-прежнему не проверено: смещения полей
пакетов конфигурации (`ic_type` заполнен ближайшим пунктом списка, для EFR32BG22 известного нам пункта нет); находит ли Home Assistant тег только по рекламе.
